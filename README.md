# АвтоЗапчасти — тестовое задание (1С-Битрикс)

Интернет-магазин автозапчастей: каталог товаров, импорт из 1С, REST API для мобильного приложения. Реализовано на чистой редакции **1С-Битрикс: Управление сайтом** (Стандарт/Малый бизнес).

📄 Архитектурные решения и обоснования — в файле **[ARCHITECTURE.md](./ARCHITECTURE.md)**
📄 Документация REST API с примерами curl — в файле **[API.md](./API.md)**

## Развёртывание

### 1. Требования

- 1С-Битрикс «Стандарт» или выше
- PHP 8.1+
- MySQL 5.7+ / MariaDB 10.4+
- Включён модуль `iblock`

### 2. Копирование файлов

Скопировать содержимое репозитория в корень сайта:

```bash
cp -r local/ /var/www/html/
cp -r api/ /var/www/html/
cp -r upload/ /var/www/html/
cp autoparts.php autoparts_detail.php run_import.php /var/www/html/
```

Если в `local/php_interface/` уже есть свой `init.php` — не перезаписывай его, а перенеси блок `Loader::registerAutoLoadClasses(...)` из репозитория в конец существующего файла (нужен для автозагрузки классов REST API).

### 3. Создание инфоблоков в админке

Зайти в **Контент → Инфоблоки → Типы инфоблоков**.

#### Инфоблок 1 — «Бренды»

- Тип: Справочники
- Название: `Бренды`
- Символьный код: `brands`
- Сайт: `s1`

Свойства:

| Название | Тип | Код |
|----------|-----|-----|
| Страна производителя | Строка | `COUNTRY` |
| Логотип | Файл | `LOGO` |

#### Инфоблок 2 — «Каталог автозапчастей»

- Тип: Каталоги
- Название: `Каталог автозапчастей`
- Символьный код: `autoparts`
- Сайт: `s1`

Свойства:

| Название | Тип | Код | Доп. настройки |
|----------|-----|-----|----------------|
| Бренд | Привязка к элементам (E) | `BRAND` | Инфоблок «Бренды» |
| Артикул | Строка | `ARTICLE` | — |
| Совместимость | Привязка к разделам (G) | `COMPATIBILITY` | Множественное, инфоблок «Каталог» |
| Цена | Число | `PRICE` | — |
| Наличие на складе | Число | `IN_STOCK` | — |
| Фотогалерея | Файл | `GALLERY` | Множественное |

#### Разделы инфоблока (модели авто)

В инфоблоке «Каталог автозапчастей» создать разделы:

- Toyota Camry
- BMW E39
- Lada Vesta
- Kia Rio
- Hyundai Solaris

### 4. Настройка ID инфоблоков

После создания инфоблоков уточнить их ID в админке и прописать в компонентах:

В файле `autoparts.php`:
```php
'IBLOCK_ID'        => 4,  // ID каталога
'BRANDS_IBLOCK_ID' => 5,  // ID брендов
```

В файле `autoparts_detail.php`:
```php
'IBLOCK_ID'        => 4,
'BRANDS_IBLOCK_ID' => 5,
```

### 5. Наполнение демо-данными

Скопировать `install/demo_data.php` в корень сайта и открыть в браузере:

```
https://ваш-сайт/demo_data.php
```

Скрипт создаст:
- 3 бренда: Bosch (Германия), NGK (Япония), Febest (Япония)
- 15 товаров с артикулами, ценами, наличием и совместимостью

**После выполнения удалить файл с сервера.**

### 6. Проверка каталога

- Каталог: `https://ваш-сайт/autoparts.php`
- Детальная страница: `https://ваш-сайт/autoparts_detail.php?ID=<ID_товара>`

### 7. Проверка REST API

Таблица токенов `autoparts_api_token` создаётся автоматически при первом запросе — никаких дополнительных миграций не требуется.

Быстрая проверка через curl (подробности и больше примеров — в [API.md](./API.md)):

```bash
curl -X POST https://ваш-сайт/api/v1/auth/token \
  -H "Content-Type: application/json" \
  -d '{"login": "admin", "password": "ваш_пароль"}'
```

В ответ должен прийти JSON с полем `token` — значит роутер и авторизация настроены верно.

## Кэширование

### Как работает кэш

Кэширование реализовано через стандартный механизм Битрикса — `startResultCache` / `endResultCache` в `CBitrixComponent`.

**Страница каталога** (`autoparts.php`):
- Время кэша: **3600 секунд** (1 час)
- Cache ID формируется из параметров фильтра и номера страницы: `md5(serialize($filter) . $pageSize . $pageNum)`
- Это значит каждая уникальная комбинация фильтра кэшируется отдельно

**Детальная страница** (`autoparts_detail.php`):
- Время кэша: **3600 секунд**
- Cache ID: `detail_{ID_элемента}`

Физически кэш хранится в `/bitrix/cache/` в виде файлов.

### При каких событиях кэш сбрасывается

Кэш сбрасывается автоматически в следующих случаях:

| Событие | Результат |
|---------|-----------|
| Редактирование элемента инфоблока в админке | Сброс кэша компонентов этого инфоблока |
| Добавление нового элемента | Сброс кэша |
| Удаление элемента | Сброс кэша |
| Изменение раздела инфоблока | Сброс кэша |
| Истечение `CACHE_TIME` (3600 сек.) | Автоматическая инвалидация |
| Ручной сброс через админку: **Настройки → Управление кешем** | Полный сброс всего кэша сайта |

Битрикс использует теги инфоблока (`iblock_id_N`) — при любом изменении элементов инфоблока все закэшированные страницы с этим тегом инвалидируются.

## Функциональность

### Каталог (`autoparts.php`)

- Сетка товаров (3 колонки на десктопе, 2 на планшете, 1 на мобильном)
- Карточка: фото, бренд, название, артикул, цена, наличие, кнопка «Подробнее»
- Адаптивный сайдбар с фильтром

### AJAX-фильтр

Фильтрация без перезагрузки страницы по:
- Бренду (select)
- Диапазону цены (от / до)
- Наличию на складе (checkbox)

URL обновляется через `history.pushState` — фильтр можно скопировать и передать.

### Детальная страница (`autoparts_detail.php?ID=...`)

- Слайдер фотографий (Swiper.js) с миниатюрами
- Артикул, цена, наличие, описание, совместимость с моделями авто
- Блок «Похожие товары» — 3-6 товаров того же бренда
- Хлебные крошки

## Задание 2 — Интеграция с 1С (импорт CommerceML 2)

### Структура файлов

```
├── local/php_interface/cron/
│   └── import_1c.php        # Консольный скрипт импорта
└── upload/1c_import/
    ├── import.xml            # Тестовый XML (20 товаров)
    └── logs/                 # Логи импорта (создаётся автоматически)
        └── import_YYYY-MM-DD.log
```

### Логика импорта

Скрипт читает `/upload/1c_import/import.xml` формата CommerceML 2 и синхронизирует товары с инфоблоком:

- **Новые товары** (нет в БД по артикулу) → создаются
- **Существующие товары** (найдены по артикулу) → обновляются
- **Отсутствующие в выгрузке** → деактивируются (не удаляются)

Идентификатор товара — **артикул** (`PROPERTY_ARTICLE`). Именно по нему скрипт определяет новый товар или существующий.

### Обработка пакетами

Товары обрабатываются пакетами по `BATCH_SIZE = 50` штук с паузой 50ms между пакетами. Это позволяет корректно работать с выгрузками 5000+ позиций без перегрузки БД и превышения лимита памяти.

### Обработка ошибок

Каждый товар обрабатывается в блоке `try/catch` — ошибка на одном товаре не останавливает весь импорт. Все ошибки фиксируются в лог с указанием артикула.

### Лог операций

Лог пишется в `/upload/1c_import/logs/import_YYYY-MM-DD.log`:

```
[15:04:35] === Старт импорта 2026-06-16 15:04:35 ===
[15:04:35] Товаров в XML: 20
[15:04:35] Брендов в кэше: 3
[15:04:35] Товаров в БД: 20
[15:04:35] Пакетов: 1 (по 50 товаров)
[15:04:35] [UPDATE] [320] Фильтр масляный Bosch P7053
[15:04:35] [CREATE] [355] Новый товар
[15:04:35] [DEACTIVATE] [310] Старый товар
[15:04:35] === Результаты импорта ===
[15:04:35] Создано:        5
[15:04:35] Обновлено:      15
[15:04:35] Деактивировано: 3
[15:04:35] Ошибок:         0
[15:04:35] Время:          0.17 сек.
```

### Настройка cron

Запуск каждый день в 03:00:

```bash
0 3 * * * /usr/bin/php /var/www/html/local/php_interface/cron/import_1c.php >> /var/www/html/upload/1c_import/logs/cron.log 2>&1
```

Путь к PHP уточнить командой `which php`.

### Запуск через браузер (для проверки)

В корне сайта находится файл `run_import.php` для удобной проверки импорта через браузер.

**Требования:** необходимо быть авторизованным как администратор Битрикса.

Открыть в браузере:
```
https://dev-wordpress.kamaylaev.ru/run_import.php
```

Лог выполнения отобразится прямо на странице. Неавторизованный пользователь получит сообщение «Доступ запрещён».

### API

Скрипт использует:
- `CIBlockElement::GetList` — чтение существующих товаров со свойствами
- `CIBlockElement::Add` — создание новых товаров
- `CIBlockElement::Update` — обновление и деактивация
- `Bitrix\Iblock\ElementTable` (D7) — чтение списка элементов без свойств (быстрее для больших объёмов)

## Задание 3 — REST API для мобильного приложения

Полная документация со всеми эндпоинтами, форматом ошибок и примерами `curl` — в файле **[API.md](./API.md)**.

### Краткий обзор

Собственная реализация REST API (без штатного `bitrix:rest`):

| Метод | URL | Назначение | Авторизация |
|-------|-----|------------|-------------|
| POST | `/api/v1/auth/token` | Получение Bearer-токена по логину/паролю | не требуется |
| GET | `/api/v1/catalog/list` | Список товаров (пагинация, фильтр по бренду) | не требуется |
| GET | `/api/v1/catalog/{id}` | Детальная информация по товару | не требуется |
| POST | `/api/v1/order/create` | Создание заказа через `Bitrix\Sale\Order` | требуется |

### Структура

```
api/v1/
├── index.php          # роутер
└── .htaccess           # маршрутизация запросов

local/php_interface/
├── init.php            # автозагрузка классов API
└── api/
    ├── ApiResponse.php
    ├── ApiToken.php
    └── Controllers/
        ├── AuthController.php
        ├── CatalogController.php
        └── OrderController.php
```

### Токены

Bearer-токены живут 24 часа, хранятся в собственной таблице `autoparts_api_token` (создаётся автоматически при первом обращении к API).

### Формат ответа

```json
{"success": true, "data": {...}}
{"success": false, "error": {"code": "...", "message": "..."}}
```
